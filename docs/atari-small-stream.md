# STREAMTEST: small NIO stream v1 on Atari

Build with the workspace library and firmware supporting small-stream version 1.
Older releases may not contain it. The established NIO game build remains
available separately.

```sh
source ../../scripts/env.sh
make atari-stream-disk
```

Disk: `build/atari/streamtest.atr`. It boots directly into the diagnostic.
It asks for a URL so you do not need to rebuild for a different server address.

On the server machine:

```sh
python3 tools/stream_echo.py --host 0.0.0.0 --port 9004
```

Allow TCP port 9004 from the Atari/FujiNet's LAN through your firewall. At the
Atari, enter `tcp://192.168.1.68:9004` (substitute your server address).
The default server bind is loopback; `--host 0.0.0.0` is needed for hardware.
The server deliberately fragments replies with deterministic random delays.

The test repeatedly writes a deterministic block and checks every echoed byte.
Block size cycles from 1 to 120. It handles partial writes and fragmented reads,
and displays completed echoes, errors, transfer size and the VBI frame counter.
Busy/NotReady are progress states, not failures. Other errors stop the test
without silently reconnecting. Q closes the stream and leaves results visible;
reset the Atari to start again.

D toggles six DLI colour bands. S toggles sound generated by the immediate VBI
using only POKEY channels 1/2. Both start enabled. The frame counter should keep
moving during network transfers. No NMI suppression, U1MB detection/table edits
or FujiNet HSIO configuration changes are performed. The polled serial carrier
always uses 19200; a FujiNet left at high speed must fall back to it.

## Hardware trials

1. HSIO off: run at least 500 echoes, toggle D/S during traffic and tap keys.
2. Reboot with U1MB HSIO and FujiNet index 0 enabled; boot the disk and repeat.
   Disk loading may be fast; network traffic should settle at 19200.
3. Stop with Q, inspect the result, reset and reconnect. Save `sio.status` before
   and after, plus logs if sound stalls, colours flash, keys are missed or errors
   occur. Note the D/S state and the last transfer size/status.

Headless AltirraSDL validation uses the real NetSIO firmware and local TCP peer:

```sh
source scripts/env.sh                 # from workspace root
python3 integration-tests/atari-sio/run_stream_test.py --output /tmp/stream-evidence
```

The test covers all 120 block sizes, verifies zero mismatches, toggles D/S,
checks VBI progression and closes cleanly. It is evidence of functional
integration, not a claim that real Atari timing is safe.

## Hardware acceptance and troubleshooting

The initial hardware failure (status 5 before the first byte) was a blocked
server firewall. After allowing TCP 9004, 459 stock-speed echoes and 600 echoes
starting with U1MB HSIO enabled passed with DLI and sound on, without errors.

Status 5 is a firmware I/O failure, not client serial failure (128). Open success
can precede TCP connection completion. Confirm the exact URL, LAN bind and firewall,
and inspect the echo server's `connected` message plus FujiNet TCP logs. Busy (3)
and NotReady (4) are progress states. Do not disable DLI/U1MB solely on status 5.

For intended users, limitations and application costs, see fujinet-nio-lib's
`docs/atari-small-stream.md`. This diagnostic deliberately stresses that API;
it is not a general performance benchmark or a replacement for game testing.
